4. สถาปัตยกรรมระบบ (System Architecture & MVC)

ระบบพัฒนาขึ้นด้วย Laravel 12 Framework บนสถาปัตยกรรม Model-View-Controller (MVC) โดยมีการแบ่งเลเยอร์การทำงานอย่างเป็นระเบียบ ดังนี้:

Model (M)

จัดการตรรกะข้อมูลและความสัมพันธ์ผ่าน Eloquent ORM:

  • User: ข้อมูลเจ้าหน้าที่/ช่าง
  • PhoneModel: ข้อมูลรุ่นไอโฟน
  • RepairService: อัตราค่าบริการ
  • Customer: ข้อมูลลูกค้า
  • RepairTicket: ใบรับแจ้งซ่อม
  • RepairStatusLog: ประวัติสถานะ
View (V)

แสดงผลผ่าน Blade Template Engine:

  • layouts.app: โครงสร้างหลักหน้าบ้าน
  • layouts.admin: เมนูด้านข้างระบบหลังบ้าน
  • frontend.*: หน้าแรก, บริการ, ติดตาม
  • admin.*: แดชบอร์ด, จัดการตั๋ว, สั่งพิมพ์
  • auth.login: หน้าเข้าสู่ระบบ
Controller (C)

ควบคุมการประมวลผลตาม Route:

  • HomeController: หน้าแรกและราคา
  • TrackingController: ระบบค้นหาสถานะ
  • BookingController: จัดการคำขอแจ้งซ่อม
  • AuthController: ยืนยันตัวตน (Auth)
  • Admin\*Controller: แดชบอร์ดและ CRUD

5. โครงสร้างฐานข้อมูลเชิงสัมพันธ์ (Database Architecture & ER)

ฐานข้อมูลของระบบประกอบด้วย 6 ตารางหลักที่เชื่อมโยงความสัมพันธ์กันอย่างสมบูรณ์ รองรับการทำงานทั้งบน MySQL (XAMPP Port 3306) และ SQLite (database.sqlite):

ชื่อตาราง วัตถุประสงค์ คีย์หลัก (PK) คีย์นอก (FK) / ความสัมพันธ์
users จัดเก็บข้อมูลผู้ดูแลระบบและช่างเทคนิค id (BIGINT) -
phone_models จัดเก็บรายชื่อรุ่น iPhone, สเปกจอ, ราคาตั้งต้น id (BIGINT) -
repair_services จัดเก็บบริการซ่อม (เปลี่ยนจอ, แบต, บอร์ด, กล้อง) id (BIGINT) -
customers จัดเก็บข้อมูลลูกค้า, เบอร์โทรศัพท์, ที่อยู่, ไลน์ไอดี id (BIGINT) Index on phone (ค้นหาเร็ว)
repair_tickets ตารางหลักเก็บใบแจ้งซ่อม, อาการเสีย, ราคา, สถานะ id (BIGINT) FK: customer_id → customers
FK: phone_model_id → phone_models
FK: repair_service_id → repair_services
FK: assigned_to → users
repair_status_logs บันทึกไทม์ไลน์สถานะและการลงมือปฏิบัติงานของช่าง id (BIGINT) FK: repair_ticket_id → repair_tickets

6. แผนผังกระบวนการทำงานของระบบ (Workflows)

กระบวนการวงจรชีวิตงานซ่อม (5-Step Lifecycle):
1
รับเครื่องเข้าระบบ (Pending) ลูกค้าเดินทางมาหน้าร้าน หรือส่งแบบฟอร์มแจ้งซ่อมออนไลน์ (Online Booking) ระบบจะออกรหัสใบรับซ่อมแบบอัตโนมัติ เช่น REP-202610-001 พร้อมบันทึกอาการเสีย
2
ตรวจเช็คอาการ (Inspecting) ช่างเทคนิครับเครื่องและเปิดตรวจสอบภายใน เช่น วัดกระแสไฟ, เช็คคราบความชื้น, ส่องกล้องไมโครสโคป พร้อมบันทึกผลการวินิจฉัยลงในไทม์ไลน์
3
ดำเนินการซ่อม / รออะไหล่ (Repairing / Waiting Parts) ช่างลงมือเปลี่ยนอะไหล่แท้ หรือดำเนินการซ่อมแผงวงจรเมนบอร์ด พร้อมอัปเดตบันทึกการทำงานเพื่อให้ลูกค้าตรวจสอบได้แบบเรียลไทม์
4
การซ่อมเสร็จสิ้น (Completed) ทดสอบการทำงานผ่าน 100% ระบบจะคำนวณวันหมดอายุการรับประกัน (เช่น ประกัน 90 - 180 วัน) และแจ้งให้ลูกค้ารับเครื่อง
5
ส่งมอบเครื่องเรียบร้อย (Delivered) ลูกค้าตรวจรับเครื่อง ชำระเงิน เจ้าหน้าที่พิมพ์ใบรับเครื่องซ่อม / ใบเสร็จรับเงิน (Print Slip) พร้อมระบุเงื่อนไขการรับประกัน

7. ระบบสมัครสมาชิกและบริการสำหรับลูกค้า (Customer Portal)

ระบบเปิดให้ลูกค้าทั่วไปสามารถสมัครสมาชิกออนไลน์ เพื่อตรวจสอบและติดตามประวัติงานซ่อมของตนเองได้แบบเรียลไทม์

ระบบสมัครสมาชิก (Registration)

เข้าใช้งานได้ที่ /register

  • กรอกชื่อ-นามสกุล, เบอร์โทรศัพท์, อีเมล, รหัสผ่าน, LINE ID และที่อยู่
  • ระบบจะ เชื่อมโยงเบอร์โทรศัพท์ กับประวัติใบแจ้งซ่อมเดิมและใหม่โดยอัตโนมัติ
  • มีระบบตรวจสอบความปลอดภัย (Password Confirmation, Email Unique)
  • เมื่อสมัครเสร็จสิ้น ระบบจะล็อกอินและนำทางไปยังหน้า งานซ่อมของฉัน ทันที
ศูนย์รวมงานซ่อมของฉัน (My Repairs Portal)

เข้าใช้งานได้ที่ /customer/my-repairs

  • การ์ดสรุปสถานะงานซ่อม: ทั้งหมด, กำลังดำเนินการ, ซ่อมเสร็จสิ้น, ส่งมอบแล้ว
  • แถบแสดงความคืบหน้า 5 ขั้นตอน (Progress Step Bar) แบบภาพกราฟิกสวยงาม
  • ปุ่มดูไทม์ไลน์ละเอียด และปุ่ม "พิมพ์ใบรับเครื่อง" ได้ทันที
  • เมื่อกด "แจ้งซ่อมเครื่องใหม่" ระบบจะดึงข้อมูลลูกค้าไปกรอกในฟอร์มอัตโนมัติ (Auto-fill)
